# 质量、媒体与安全

[English](../en/quality-media-safety.md) | [简体中文](../zh-CN/quality-media-safety.md)

## 深度等于穷尽有效证据

所有完整笔记都使用 deep profile，但不设置机械字数。目标是穷尽有用的一手
证据，不为短论文填充篇幅，也不捏造缺失细节。

- 章节 `0` 通常包含 3-5 个密集段落。
- 章节 `1-2` 完整解释问题、产物、证据、前序路线、直接替代和准确定位。
- 论文特定的章节 `3-4` 在证据允许时通常各含 3-6 个实质小节。
- 核心小节通常同时解释机制/设置与解释/边界。
- 章节 `5-7` 不能退化为泛化收尾。
- 章节 `8` 对版本、发布、复现和后续工作做有注释的整理。

论文类型仍决定内容。Benchmark 笔记重点是构建、污染、协议、基线和有效性，
不能套成模型架构报告。

## 证据锚点

每个保留的 Figure/Table 记录：

- 正式编号和忠实 caption。
- 来源页码或稳定来源 URL。
- 它支持的主张。
- 紧邻的结果解释及解释边界。
- 可选稳定媒体，以及许可或授权依据。

证据丰富的论文通常保留 5-8 个有效锚点；论文本身素材更少时，数量更少才是
正确行为。

## 媒体模式

`markers` 是默认值，不复制媒体也能准确导航证据。

`extract` 默认精选 3-6 个最重要视觉项，例如核心架构、决定性主结果、
关键消融、代表案例或关键效率证据。每个 crop 都要与正式编号、caption 和
上下文核对。

`off` 只省略独立媒体块，不免除正文解释关键证据的责任。

## 权限与来源

能够访问 PDF 不等于拥有复用许可。自动提取必须基于开放许可、用户提供的
材料或明确授权；否则回退到 markers。

不得删除 attribution 或水印，也不能为了示例把整篇 PDF 提交到仓库。
仓库素材使用稳定文件名，并由 media manifest 记录来源、页码、用途和许可。

## 隐私与秘密

公开工件不得包含：

- API key、OAuth token、cookie、client secret 或凭据文件。
- 私有 database/page/document/user/tenant/upload ID。
- 签名或短期媒体 URL。
- 本地绝对路径、私有属性 schema 或个人默认值。

CI 对完整 Git 历史运行 Gitleaks，并检查配置、fixture 秘密模式、XML 解析
和链接。真实平台冒烟测试只在 PR 中记录脱敏状态与数量；读回和截图后删除
带测试标记的临时文档。
